# Multi-Agent Upgrade — Self-RAG Pipeline (Rewriter · Grader · Verifier · Memory Condenser)

Upgrade the LangGraph core from the current linear `planner → retriever → responder` flow to a Self-RAG/CRAG-style multi-agent pipeline with quality loops, all driven by the workspace's learned profile. One retry per loop, hard-capped, so queries can never loop forever.

## New pipeline

```
START → planner (intent only) → condenser (only if history is long)
  ├─ conversational ──────────────► responder ──► END (no verification needed)
  └─ retrieval → rewriter → retriever → grader
                     ▲                    │
                     │  (0 relevant,      │ ≥1 relevant chunk
                     │   retry < 2)       ▼
                     └──────────── responder → verifier
                                       ▲         │ pass → END
                                       │         └─ fail & revision < 1 → regenerate
                                       └──────────────┘
```

## The four new agents (`app/agents/nodes/`)

1. **`rewriter.py` — Query Rewriter**: turns the user's message + conversation context into one standalone search query ("what about its memory?" → "memory requirements of X from the earlier answer"). On a retrieval retry it deliberately rephrases more broadly. One LLM call; sets `search_query`.
2. **`grader.py` — Document Grader (CRAG)**: grades ALL retrieved chunks in a single batched LLM call (JSON list of relevant indices) — cheap despite being an agent. Filters junk out of the context. If nothing is relevant and retries remain → send back to the rewriter; if nothing after retry → force an honest "not in the knowledge base" answer instead of a hallucination.
3. **`verifier.py` — Answer Verifier (Self-RAG)**: checks the draft answer against the graded context in one call (`SUPPORTED`/`UNSUPPORTED` + reason). Unsupported answers get regenerated once with a stricter grounding instruction; still failing → returned with a `verified: false` marker.
4. **`condenser.py` — Memory Condenser**: when a conversation exceeds ~10 messages, condenses the history into a compact summary once (stored in state) so later prompts stay small — improves follow-up quality AND keeps us under Groq rate limits.

## Modified files

- `app/agents/state.py` — add `search_query`, `retrieval_attempts`, `graded_documents`, `answer_revision`, `verified`, `condensed_history`.
- `app/agents/graph.py` — new nodes + conditional edges with the two retry loops.
- `app/agents/nodes/planner.py` — simplified to pure intent classification (rewriting moves to the rewriter).
- `app/agents/nodes/retriever.py` — retrieves with `search_query`, reranks to top 8, increments attempt counter.
- `app/agents/nodes/responder.py` — answers only from graded chunks; honest-refusal path when grading found nothing; revision-aware prompts.
- `app/agents/prompts.py` — new profile-driven builders: rewriter, grader, verifier, condenser + no-context responder variant.
- `app/api/routes_chat.py` — response now also returns `verified` and richer `thought_process` steps (e.g. "Graded 15 chunks → 4 relevant").
- `frontend/src/pages/Chat.jsx` — small: show a ✅/⚠️ verification badge on answers (reasoning steps already render automatically).
- `scripts/e2e_verify.py` — extended to assert the new steps appear and the `verified` flag is returned.

## Trade-off handling (free-tier rate limits)

- Grader + verifier are single batched calls, not per-chunk.
- Memory condensing runs only for long conversations.
- All calls go through the existing `chat_completion` helper (primary→fallback + 429 backoff).
- Conversational answers skip the verifier (nothing to ground).
- Worst case per query: ~4 extra LLM calls; typical case: 1–2.
